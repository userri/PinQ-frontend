# 핸드오프 — 정원 후광 · 개념 진단 · 마이페이지 (2026-08-05)

세션이 끝난 시점의 상태와 다음 사람이 이어받을 것.
**대기 작업의 단일 진실은 여전히 `PinQ-backend/docs/PENDING.md`** 다 — 여기 적힌 "이어서 할 것"도
거기 한 줄씩 들어가 있다. 이 문서는 맥락만 담는다.

## 끝난 것

### 1. 정원 후광이 하나뿐이던 문제 (`2ea7327`)

배지는 `오늘 물 줄 잔디 5개`인데 후광은 1개였다. 우선순위가 둘이었던 탓 —
복습 큐(서버)는 `stage` 상위 5, 정원 앞줄(클라)은 졸업→`stage`→`waterCount` 상위 13.
앞줄만 개별 식물로 그리고 나머지는 능선 뒤 실루엣이라, due 5개 중 앞줄에 든 게 하나였다.

**앞줄에 due 를 먼저 채우고 남는 자리를 성장 순으로** 바꿨다. due 는 큐 상한(5)까지라
전시용 자리가 최소 8칸 남는다. 실기기에서 배지 5 = 후광 5 확인.

### 2. 개념별 정답률 (`2ea7327` → `c6669da`, 커밋 5개)

빨강이 서버 `weakest` 하나에만 붙어 있었다. 같은 58% 인데 환율만 빨갛고 부동산은 라임 —
사용자는 빨강을 "나쁘다"로 읽는데 실제 의미는 "최저 하나"라 색이 거짓말을 했다.

최종 모양은 **다섯 상태**다. 규칙과 근거는 `docs/ui-rules.md` §1·§6, 서버 쪽 한계는
`PinQ-backend/docs/rules/concept-diagnosis.md`.

| 상태 | 문구 | 빨강 |
|---|---|---|
| 표본 부족 | 조금 더 풀면 취약 개념을 진단해드려요 | 없음 |
| 미달 1개 | `환율 개념이 흔들려요` · `43문제 중 25개 정답` | 그 하나 |
| 미달 2~3개 | `환율 · 부동산 개념이 흔들려요` | 그 둘 |
| 미달 4개 이상 | `4개 개념이 흔들려요` | 그 넷 |
| 전부 미달 | 아직 익숙해지는 중이에요 | **없음** |
| 전부 기준 이상 | 모든 개념이 안정적이에요 | 없음 |

핵심은 **경고색 집합 = 배너가 부르는 집합**이라는 것. 처음엔 빨강은 "미달 전부", 배너는
"동률 최저"를 말하게 두고 "역할이 다르니 모순 아니다"로 정리했는데, 화면에서는 이름 없이
빨간 줄이 남는 구멍이었다. 같은 실수를 반복하지 않으려면 §6 첫 항목을 볼 것.

`weakest` 를 상대 기준으로 뽑는 규칙은 서버가 하나만 내려주던 시절의 흔적이라 걷어냈다.
**프론트는 이제 `weakest` 를 쓰지 않는다.**

- 진단 로직: `ConceptStatsSection.conceptDiagnosis()` — 순수 함수, 테스트 8개로 전 상태 덮음
- 눈으로 볼 곳: `ShowcaseActivity --es screen concept_tie` (다섯 케이스가 세로로 붙어 있음)

### 3. 마이페이지 도움말·의견 (`a84297c`, 이전 세션)

`앱 정보` 아래에 버전과 뭉뚱그려져 있던 두 항목을 별도 섹션으로 뺐다. 앞에 아이콘 열을
세워 형태부터 다르게 했고(면은 안 늘림), `2분이면 됩니다 · 익명` 을 붙였다.

### 4. 규칙 문서 정리

소유자로 갈랐다. 자세한 건 `docs/README.md` 색인.

- 도메인 규칙 → 백엔드 `docs/rules/` (`grass-and-streak.md`, `concept-diagnosis.md` 신설)
- 표현 규칙 → 프론트 `docs/ui-rules.md` 신설. **값 복사 금지, 링크만**

이중 관리되는 값은 최소 표본 **3** 하나뿐이다
(`MIN_ATTEMPTS_FOR_DIAGNOSIS` ↔ `ConceptStatsSection.MIN_SAMPLE`).

## 이어서 할 것

### 실서버 마이페이지 확인 (남은 검증)

개념 섹션은 **Showcase 로만 봤다.** 실기기에서 실제 계정의 마이페이지를 열어 다섯 상태 중
어느 것이 뜨는지, 문구가 실제 데이터와 맞는지 확인이 남았다. 정원 후광은 실데이터로 확인함.

마이페이지는 SWR 캐시라 값이 바로 안 바뀔 수 있다 — 판정이 애매하면 logcat 말고
토큰으로 `GET /api/users/me/concept-stats` 를 직접 호출해 볼 것.

### 릴리즈

`versionCode` 는 사용자가 직접 관리한다. 이번 변경을 배포하려면 버전을 올리고 릴리즈
빌드를 만들어야 하는데, **손대지 말고 사용자에게 물을 것.**

### 열어둔 문 (지금 안 해도 되는 것)

- **"요즘" 을 되살리려면** 서버 `countByCategory` 에 기간 파라미터가 필요하다. 지금은 전체
  기간 누적이라 최근 추세가 아니다. 창(예: 30일)을 도입하면 그 안에서 표본 3개를 못 채우는
  사용자가 대부분일 수 있으니 최소 표본 기준도 같이 재검토해야 한다.
- **`weakest` 응답 필드**는 프론트가 안 쓰게 됐다. 다른 소비자가 없다면 정리 대상이지만
  급하지 않다. 서버에서 이 값을 손볼 일이 생기면 프론트가 안 쓴다는 점을 먼저 확인할 것.
- **문서 위치 이관** — `docs/ui-rules.md` 는 PENDING 에 이미 있는 이관 항목 ②에 해당한다.
  이번에 새로 만든 파일이라, 그 작업을 할 때 같이 옮기면 된다.
